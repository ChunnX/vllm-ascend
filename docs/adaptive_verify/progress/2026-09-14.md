## 1. 关键 bug:confidence head 在 FULL 图下被"冻结"——已定位并修复

- **现象**:换低接受率单请求样本后,FULL_DECODE_ONLY 下 `[DSPARK-AV-OBSERVE]` 的 conf 逐位
  在 ~30 个窗口里**一字不差**(恒为 `0.790/1.000/0.922/0.940/0.845/0.943/0.833`),而实测
  acc 随位置从 ~0.72 陡降到 ~0.05。早期代码题(接受率 96–98%)得出的"FULL 图下 conf 正常"
  是假象(啥都接受,conf≈acc≈1 掩盖了问题)。
- **对照**:同样本加 `--enforce-eager`,conf 立刻逐窗口变化、随位置单调下降 → 证明是图捕获
  冻结,不是 head 坏。
- **根因**:上游 `_sample_sequential` 的 confidence 计算被 `if enable_adaptive_verification`
  门控;而 `DFlashSpeculator.capture()` 直接 trace `_generate_draft`(绕过 observe 翻 flag
  的 `propose`),捕获时 flag=False → confidence 算子没进 FULL 图 → 回放永不重算 → 冻结。
- **修复(两处)**:
  - `565add069` `AscendDSparkSpeculator.capture()`:捕获前把 flag 置 True(仅 observe/shadow
    时),setup 阶段仍 False → 不建裁剪管理器,捕获时 True → confidence 分支入图、每步重算。
  - `c34abc4c7` `ModelWithContext` 补 `compute_confidence` 代理:ACLGraph 包装器只显式代理
    固定几个方法、无 `__getattr__`,捕获时 confidence 分支 `AttributeError`,按同款补上。
- **验证通过**:修复后 FULL_DECODE_ONLY 重跑,捕获无报错,conf **逐窗口变化、行内随位置下降**
  (首行 `0.777→…→0.398`),且与 eager 逐位几乎重合 → 捕获图忠实复现 eager 置信路径、无精度
  损失。**图模式(生产/高并发)的 AV 前提由此打通。**
- 证据日志(NPU):`docs/logs/20260914/` 下 `...full_decode_only-mean-acceptance-3.log`(冻结)、
  `...eager-mean-3.log`(活)、`...graph-revised-09141600.log`(修复后活)。

## 3. 16 并发 specbench_zh 观测:裁剪空间有,但 confidence 尾部过自信

- 聚合 112 窗口(mean_accept_len~3.62):

  | pos | conf | acc | gap |
  |---|---|---|---|
  | p0 | 0.791 | 0.746 | +0.045 |
  | p3 | 0.625 | 0.309 | +0.316 |
  | p6 | 0.516 | 0.150 | +0.366 |

- **裁剪空间存在**:p4–p6 只接受 15–24%,却每步陪跑验证(非代码题场景有肉)。
- **conf 排序对、绝对标定尾部过自信**:把衰减压扁(acc 跨 0.75→0.15,conf 只跨 0.79→0.52)。
  manager 用 survival=cumprod(conf),尾部虚高 → 会少裁。修正早期"标定良好"结论(那是代码题
  平凡假象)。
- **calibration 结论**:上游用 raw confidence、无按数据集重标定;标定是 checkpoint 训练的责任。
  尾部过自信当作该 checkpoint 的体检结论,**不做下游 affine 拟合**(不具通用性)。
- 反馈同步进 `docs/`(独立仓)`pr15098_..._feasibility.md §7`(commit `c88e1b5`)。

## 4. 上游两 PR + RFC 梳理:能不能"直接合"

- **RFC #15149**(总纲,OPEN):点名 Qwen3.5/3.6 的 GDN 变长 state 正确性是核心难点;并明确
  "removing a few logical tokens is useful only when it reaches a cheaper execution shape"
  —— 官方印证了 flat-cost 判断。
- **#15098**(OPEN):AV"大脑",`model_runner` 接 compact/reallocate/get_num_tokens(+66 行),
  attention 后端(dsa/sfa/mla)变长;实测 Qwen3-8B +12%、DeepSeek-V4-Flash +22%(draft=9),
  **都是 attention 目标,无 GDN 分支**(DeepSeek draft=7 甚至 −7%,收益依赖 draft 长度/规模)。
- **#15207**(OPEN):GDN 变长算子 `npu_dcut_causal_conv1d` / `npu_dcut_recurrent_gated_delta_rule`
  (吃 query_start_loc+cache_indices+num_accepted_tokens,注册 910B/910_93/950),**只加算子+UT,
  没接进 gdn.py/gdn_attn_builder/AV 路径**。
- **结论**:GDN 动态校验能力其实已存在(ascend `gdn_attn_builder`+`gdn.py` 已用 num_accepted_tokens
  滚 conv/ssm 态,是现在 spec decode 能跑的原因)。两 PR 各做一半,**缺的正是把 #15207 算子接进
  GDN 前向 + 让 GDN 元数据按 compact 后变长重建——这块是唯一原创工作量。** 策略:跟随 RFC #15149,
  能采纳就采纳。
